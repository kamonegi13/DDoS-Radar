# P5 — ACCIDENTAL 155 件の裁定

**背景**: Phase S の仕様書は「実装がそうなっているが、意図してそうしたのか誰も分からない挙動」を
ACCIDENTAL として 155 件記録した。これはオーナーが感じていた「追加に追加を重ねた複雑化」の実体であり、
**裁定して減らすこと自体が simplification** である。

**判定の物差し**: ツール定義 4 文 + NP1-NP7 / AP1-AP4 + [P4-processing-steps.md](P4-processing-steps.md) の
11 ステップ責務分解（特に §5 基準 2「隣接ステップの責務が重ならない」）。

**一次分類の出典**: `_drafts/ACC-groupA〜D.md`（全件の挙動・根拠・単純化効果・リスクを記載）。

## 1. 裁定結果

| 分類 | 件数 | 意味 |
|---|---:|---|
| **KEEP** | **6** | 意図的かつ正しい。または廃止すると検知能力が落ちる |
| **DROP** | **35** | 何の役にも立っていない、または原則に反する。**廃止すると単純になる** |
| **SIMPLIFY** | **86** | 必要な挙動だが現在の形が必要以上に複雑 |
| **OWNER** | **20** | 真の裁定事項（**論点重複を束ねて実質 13 決定**、§4） |
| 裁定不要（climate 凍結 ADR-V3-008） | 8 | |
| **計** | **155** | |

### 最も重要な数字: KEEP は 155 件中 6 件

**「意図的で正しい」と言えるものが 4%** しかない。残り 96% は、方針転換の残滓・急ぎの対処・
コピペの派生・利用されなくなった機構である。これがオーナーの体感「複雑化」の実体だった。

**訂正的な補足**: これは「過去の判断が杜撰だった」ことを意味しない。ツールは 3 回の較正災害を
乗り越え、recall 0.966 を維持している。**正しく機能している部分は ACCIDENTAL ではなく CORE として
仕様化されている**（765 条項のうち ACCIDENTAL は 155、残り 610 は CORE / DEFECT-PRESERVE）。
ここに集めたのは「決めた記憶が無い」部分だけである。

## 2. 複雑さは 155 個の独立した問題ではない — 8 本の根本原因に集約される

各群の分析を突き合わせると、155 件は少数の型に収束する。**これが「見通しが悪い」ことの機構**である。

| # | 根本原因 | 該当件数 | どのステップの問題か | 処方 |
|---|---|---:|---|---|
| **R-1** | **ステップ責務の混線** — ある挙動が P4 の 2 ステップにまたがる（S1 が S2 の件数を推測する / S4 の閾値がセンサー内にある / S5 の関連性フィルタがセンサー内にある 等） | **約 33** | S1〜S5 全般 | **P4 のステップ境界を実装境界にする**。個別に直すと特例が一段増えるだけなので、**まとめて解く** |
| **R-2** | **同じ語で 2 系統** — What-If が純クライアント側とサーバ反映側の 2 種、ゲートが 3 重定義、結論不可の表現が複数 等 | **約 21** | S6 / S7 / S8 | 用語を分けるか一方を廃止する。**1 本の修正で複数件が同時に閉じる** |
| **R-3** | **fail-open**（欠測・不確実を「健全」「許可」と読む） | **約 12** | S3 / S4 / S9 | ADR-V3-006 の機械適用。**新規判断を含まない** |
| **R-4** | **廃止された原則の実装残滓** — 旧 P5「ツールは判断しない」由来の隠蔽、v1 互換経路、移行足場 | **約 15** | S6 / S11 / 契約 | 削除。NP4 が旧 P5 を完全廃止済 |
| **R-5** | **死んだ機構** — 利用 0 件の validator、常に 0 の指標、到達不能な状態、未参照の閾値 | **約 14** | 全般 | 削除 |
| **R-6** | **設定到達性の欠如** — registry に登録済みだが実行時に読まれない | **約 8** | S4 | D2 G-15（96/98 キー）に帰着。**個別ではなく到達性機構そのものを直す** |
| **R-7** | **記録の欠落** — 判断したのに台帳に残らない（AP1 の順位、抑制の理由、ガードの発火） | **約 9** | S8 / S11 | P4 S11 の責務として一元化 |
| **R-8** | **文書と実装の乖離** — docstring・設計文書が実装と食い違う | **約 8** | 全般 | 仕様書（Phase S）を正本とし、docstring は参照に格下げ |

**この表が示すこと**: 「複雑さ」は 155 個の判断ではなく、**8 本の処方**である。
そして R-1 と R-2 だけで **54 件（35%）** を占める。両者はいずれも
**「どのステップが何をするか」が決まっていなかったこと**の帰結であり、P4 が直接の回答になる。

## 3. DROP 35 件が消すもの（単純化の実体）

削除で何が減るかの代表例:

| 対象 | 消えるもの | 根拠 |
|---|---|---|
| background TL の隠蔽（`SHOW_BACKGROUND_TL`） | 設定キー 1 + 応答分岐 1 + 「計算したのに隠す」不透明さ | **NP4 に正面から反する旧 P5 の残滓**。しかも隠蔽の 2 行上で「LITE モード」の注意書きを既に付けている（= 限定性を伝える機構は既にある） |
| LLM プロンプト永続化の既定 OFF | フラグ 1 + 分岐 1 | **NP6「プロンプトまで遡及可能」と正面から矛盾**。機構は実装済みなので常時 ON にするだけ |
| `shadow_dual` 状態 | 到達不能な状態 + **並行 shadow 呼出し機構ごと**（LLM コスト倍増機構） | 3 述語すべてで偽 = 死んだ状態 |
| registry の enum/validator 機構 | 機構一式 | **利用 0 件**。代替は S5 の `unit` 型宣言 |
| `name_en` / `description_en` / `lang` 列 | DB 列 3 + 分岐 | 日本語専用化で表示経路が消滅済み |
| WS トークンのクエリ文字列受理 | 互換経路 1 | ws.py は rewrite 確定。かつ**秘密がログに残る** |
| SPOF の「代替手段あり」欄 | 常に偽の固定値 | 仕様すら存在しない |
| 英 FCDO パーサの「travel を含めばレベル 2」 | fail-open 分岐 1 | 実質「不明 = レベル 2」で**偽の引き上げ**を作る |
| ATTENTION 一覧要求での二重収集 | 重複処理 1 | **ヒステリシスが要求頻度に依存する**（性能でなく正しさの問題） |
| FOCUSED_ONLY 名簿の二重管理、常に 0 の `gov_count`、3 値語彙外の `mixed`、未参照の閾値 3.0、v1 永続キー ほか | 各 1 | 死んだ機構 |

## 4. オーナー裁定事項 — 20 件を 13 決定に圧縮

論点が重なるものを束ねた。**各件に推奨を付す**。

> **裁定結果（2026-08-06）**: O-1〜O-13 の全 13 決定を、下表の推奨どおり**オーナー承認**。
> 以後は実装既定として扱う（覆す場合は ADR を記録）。O-13 のみ補足: P6 O-18 の設定二分に従い、
> registry へ移すのは運用可変キーのみ、固定閾値は provenance 付き定数を API で開示する形とする。

### 検知の感度に関わるもの（NP1 直結）

| # | 決定 | 推奨 | 備考 |
|---|---|---|---|
| **O-1** | **TL1 が領域数を要求しない**（TL2 は 2 領域要求。NP2 と逆転） | **ADR-V3-004 どおり cutover 後に裁定**。それまでに L5 で「TL1 発火時の active_domains 内訳」統計を採る | 統計なしに決めると NP6 違反 |
| **O-2** | **軍事演習の LLM 判定が physical に入り TL1 ゲートに寄与** | **domain は維持し、TL1 にのみ「一次観測ドメイン」要件を課す** | NP4（結論最大化）と NP5+8（品質規律）の緊張点。O-1 と連動 |
| **O-3** | **攻撃モード閾値を観測分布に追従させる運用の是非**（2 回引き下げ済） | **追従をやめ、S9 の教師信号に一本化** | 常時点灯は「絶対閾値で定義すべきでない指標」のサイン。S9 稼働が前提 |
| **O-4** | **greynoise の抑制範囲**（現在は自分のエントリしか抑制しない） | 抑制範囲を明示的に定義する（現状は非対称で意図不明） | NP1 に直結。適用漏れも過剰適用も危険 |
| **O-5** | **tier 降格に recall 劣化軸を入れるか** | **入れる** | ただし D2 D-01「測定系のバグは構造では直らない」が固有リスク |

## 6. この裁定が示したこと

1. **複雑さは 155 個の判断ではなく 8 本の処方だった**。しかも R-1 と R-2 で 35% を占め、
   両者とも「どのステップが何をするか」が決まっていなかったことの帰結である
2. **KEEP は 6 件（4%）**。ツールが壊れていたのではなく、**決めた記憶の無い挙動が沈殿していた**
3. **オーナー判断は 155 件 → 13 決定**。残り 142 件は原則と既決 ADR から一意に導出できた
4. **P4（ステップ分解）が最大の武器だった**。「隣接ステップの責務が重ならない」という 1 つの基準が、
   33 件を機械的に検出した。**見通しを良くする設計が、そのまま複雑さを測る物差しになった**
