## 2. 横断所見

### 2.1 「同じ語で 2 系統」型 — 15 件

同一の概念・語彙が **2 つの独立した系統（実装・値・スコープ・定義）で並存し、どちらが正か仕様上決まっていない**もの。
P4 §5-2「隣接ステップの責務が重ならない」に直接違反し、見通しを最も損なう族。**全件が SIMPLIFY 以上**。

### 2.2 閾値の所在 — 5 件が 1 つの構造欠陥の顕在化

S1-A2 / S1-A4 / S1-A12 / S2-A5 / S4-A1 はいずれも「結論に影響する値がどこにあるか」の問題であり、
**D2 G-15（登録 98 キー中 96 キーが 3 層解決を迂回。registry が実質的に装飾）の各面での現れ**。
P1 §12「直読み禁止を型で強制」が入れば 5 件とも同時に解消される。個別裁定は不要で、
本書は「registry 実効化の対象に含める」ことだけを記録する。

## 4. オーナー裁定 — 10 件を 7 決定に束ねる

同じ論点が複数冊に分裂しているだけの組があるため、裁定の単位は 10 でなく 7。

| # | 決定 | 束ねられる ID | 推奨 |
|---|---|---|---|
| **D-1** | **アナリスト状態のスコープ** — ack / snooze / dismiss を per-user にし、サーバ台帳に載せるか | S1-A6, S2-A4（+ S2-A8 の認可規則） | **per-user + サーバ台帳化**。P4 S8 の入力にアナリスト状態が明記されており、S8 をサーバへ移す（D2 G-03 解消）際に不整合を生まないため。単独運用では体感差ゼロ、後から足すと台帳のスキーマ変更を伴う |
| **D-2** | **cutover 運用** — rollback の発火主体と旧系の稼働形態 | S5-A5, S5-A6 | **手動 rollback（自動は「要求」の提示まで）＋ 旧系は信号台帳からの replay 専用**。2 件は同じ「切り戻しの即時性をどこまで買うか」の裏表。外部 API の 2 倍消費は D2 A-10 の耐性から見て危険 |
| **D-3** | **cutover ゲートの数値条件** — パリティ下限と recall 基準区画 | S5-A1, S5-A2 | **下限は先に固定**（緩めると根拠が消える）。ただし「予期された差分」の機械的分離を条件に加える。**attack_mode 系は recall 判定の対象外と明示**し、退化は S10 の系譜健全性検査で観測を継続 |
| **D-4** | **保持期間の分類規則** — retention 未定義 17 表 | S3-A1 | **3 分類（NP6 系譜=恒久 / パリティ窓連動=60 日 / 学習観測=窓）**。裁定が要るのは「恒久」の範囲だけ。個別判断 17 件が分類 3 件になる |
