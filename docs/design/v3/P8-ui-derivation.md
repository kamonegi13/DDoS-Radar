# P8 — UI 導出設計(WP-4.0 成果物 2/2)

**位置づけ**: P6 O-19 の裁定に基づく WP-4.0 の成果物。**現行画面を出発点にせず、アナリストの一次ループと
出力 O-1〜O-12 から画面を順方向に導出**する(ADR-V3-003 の UI への適用)。S1-frontend-behavior の 72 条項は
ミクロ挙動(同期・エラー処理・無害化等)の参照元として有効だが、**画面構成・表示物の存廃は本書が優越する**(§7)。
本書の裁定も「**推奨 = 実装既定**」。
**オーナー承認（2026-08-06）**: 確認推奨としていた 4 裁定（SALUTE 等の報告 1 系統化 / 地図の Tier 1 降格 /
Watchpane 廃止 / AP3 合成 1 チップ化）を含め、本書の裁定は**全件承認済**。

**導出原則**:
1. **画面はアナリストの問いに答える**。P4 がステップに 1 問いを与えたのと同じ規律を画面に適用する
2. **段階的開示**。常時表示(Tier 0)/ 1 クリック(Tier 1)/ 監査時(Tier 2)の 3 階層。
   「常時表示に値するか」を問わない要素は置かない
3. **表示は射影**。採点・順位付け・説明生成はフロントで再実装しない(G-09 の禁止、P7 R2/R6/C6)
4. 日本語専用・panel-chrome 契約・`_escHtml` 無害化・WCAG 配慮は現行規範を維持(S4 / S1-UI-041/046)

## 1. アナリスト一次ループ(1 枚)

ツール定義: アナリストは**組織的判断プロセスの一ノード**としてこのツールを使う。日次の基本動線:

```
 ① 状況確認 ──「何か変わったか？ 今このツールを信じてよいか？」──── 目標 10 秒
 │    状況ボード: シナリオごとの TL・トレンド・前回確認からの変化、合成信頼度チップ、NP7 常設
 ▼
 ② トリアージ ──「次に何を見るべきか？」──────────────────── 目標 30 秒
 │    注目レーン: S8 順位(根拠つき)を上から。ack/snooze はここで
 ▼
 ③ ドリルダウン ──「なぜそう言えるか？ 何が起きたか？」────── 必要なだけ
 │    結論詳細: 5 結論型 + 結論不可 → 平文説明 → 導出連鎖(式→閾値→兆候→観測→一次ソース)
 │    → 反証(何があれば TL が動くか) → 異常事象の時系列・地理
 ▼
 ④ フィードバック ──「ツールの判断は正しかったか？」──────── 都度
 │    ラベル投稿・インテル裁定・提案の適用/却下
 ▼
 ⑤ (週次)検証 ──「この系は生きているか？ 過去の判断は妥当だったか？」
      自己評価詳細・判断台帳・Replay・設定
```

**この動線が画面の一次構造である**。①②が Tier 0、③④が Tier 1、⑤が Tier 2。
現行 UI の「地図が主役・HUD 3 段 約 20 チップ常設」は①の 10 秒要件を満たさないため採らない(§6)。

## 4. AP3 合成信頼度(12 チップ並列の置換)

AP3 の要件は「今このツールの結論をどこまで信じるかを**アナリストが秒で判断できる**」。12 チップ並列はこの要件と
矛盾する(読むのに秒では足りない)。設計:

- **合成 1 値**: `trust = min(recall 状態, null-zone 状態, drift 状態, L5 監視群の最悪値, 鮮度状態)` の
  **min 合成**(最悪値支配)。NP1 と整合 — 1 系統でも疑わしければ全体を疑う
- 3 段(青 = 通常 / 琥珀 = 留保つき / 赤 = 結論を信じるな)+ **理由スロット**(「drift 検知中」等、最悪要素を 1 語で)
- 合成式・各要素の実効値・境界は R7 が返し、tooltip の決定論テンプレートで開示(式を隠さない — NP6)
- 内訳 12 指標は自己評価詳細(Tier 2)に残る。**消えるのは常時表示だけ**
- HUD Row 3 の境界値フロント直書き(P5 O-13)は R7 供給に置換されて解消

## 6. 地図の裁定(主役からの降格とレイヤ半減)

順方向導出で地図が答える問いは「**異常はどこで起きているか**」(O-4 の地理面)だけである。
状況確認(①)の問いには状況ボードが答える。よって:

- **地図は Tier 1**。起動時の主役ではない(v1 の地図中心レイアウトを継承しない)
- **残すレイヤ**: participant マーカー(役割が第一次元 — S1-UI-060 継承)、異常事象マーカー、
  シーケンス連鎖の地理表示、静的参照(チョークポイント・ケーブル・ISR 名所 — トグルで既定 OFF)
- **落とすレイヤ**: 脅威地形・連携リンク(較正が「信号を持たない」と判定済 — S1-frontend A15/A16)、
  センサー環・脅威ハロー(TL/寄与の重複表示かつ同一方位角で判読不能 — A11)、DDoS 時代の全レイヤ(DP15 確定済)
- レイヤ選択・対話状態は永続する(S1-UI-057 の欠陥を解消)

## 9. 追補 — 表現面の導出(NP9、2026-08-14)

**発端**: 定義改訂(CLAUDE.md 5 文化)と NP9 の成立。本書 §1 のループは**結論の読者**としての
アナリストを導出基盤とし、観測の**表現**という成果物を持たなかった(P9 §1.7 の根本原因分析)。
本追補はその欠落を埋める。§1〜§8 の結論系導出は不変。

**表現面の Tier 配置**:
- **Tier 0(状況ビュー)**: 観測レイヤ — 全観測国(掃引努力の濃淡を併示: 密掃引 / 全球掃引 /
  未掃引の 3 帯)+ 結論の彩色(現行)。Replay スクラブ(時間軸の操作)
- **Tier 1(シナリオ面)**: 事象地図(現行の geo 面)・What-If 操作面(C6)
- **Tier 2**: 相関等の関係射影(要建造、供給が先)

**供給規律(NP9 の実装解釈)**:
1. 掃引努力は**読み側で導出する** — カタログ(宣言された掃引計画)× fetch_log(実行結果)の
   結合射影。tick の書き込み変更は行わない(C-16 の 30 日時計を守る)。カタログは tick と同一
   モジュールを読むため第 2 読者問題(A-02)を生じない
2. 時間窓の約束: 観測レイヤ ≦ **60 日**(SIGNAL_RETENTION_DAYS)、Replay ≦ **90 日**
   (R3 読み上限)。保持と読みの上限を超える表現を約束しない
3. 表現は R 射影のみから描く。フロントでの導出禁止(G-09)は表現面にも適用

**v1 sunset の前提追加**: cutover 後の v1 sunset(D+90)は、パリティ 17 条件に加えて
**P9 §6 のオーナー実見ゲート(表現の受け入れ)合格を前提とする**。パリティが緑でも表現が
未受け入れのまま v1(表現の現行担い手)を消す経路を封じる(P2 §計画への波及)。
