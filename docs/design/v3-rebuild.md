## 0. 経緯と決定

2026-08-03、オーナーから「機能の逐次追加によりツール全体が有機的に連結した最適形になっていない」
との問題提起と、完全スクラップ＆ビルド（蓄積データ破棄も許容）の提案があった。

評価の結果、**完全新規構築（データ破棄込み）は棄却**し、
**データ・テスト・較正実績を連続させた段階的全面リビルド**を採用（ADR-V3-001）。
最終状態は「コードの大半が新しく、境界が原則から再設計され、較正と検知実績が途切れていない系」。

棄却理由（前方視のみ。サンクコストは根拠に含めない）:
1. ツールの価値はコードではなく**較正済み稼働系**（ラベル・ベースライン・ledger・実戦検証済み挙動）にある
2. このドメインの回帰は沈黙する（calibration インシデント #1〜#3 は全テスト通過のまま数週間 prod を劣化させた）。
   検証は 30 日窓のラベル蓄積に律速され、コスト度外視でも暦時間は買えない
3. データ破棄はツール定義が「設計失敗」と定める恒常的結論不可（null-zone）状態を自ら選ぶ行為。
   DB 持ち越しはほぼ無料、再構築だけが高い
4. 旧コードを仕様書代わりにした転写は同型の系に収束し、原則だけから書くと細部挙動
   （dedup キー、ゲート条件）が失われる。ゆえに**仕様の完全下ろし（Phase S）が前提条件**

## 1. プログラム原則

| # | 原則 |
|---|------|
| R1 | **データ連続**: ground-truth ラベル・AP3 anchor ラベル・ベースライン・conclusions ledger は移行する。破棄しない |
| R2 | **仕様先行**: 新コードは旧コードからではなく、Phase S の挙動仕様書から書く |
| R3 | **パリティゲート**: cutover 条件は数値で先に決める（replay 30 日窓で recall ≥ 旧系）。「綺麗だから」で切り替えない |
| R4 | **旧系を止めない**: shadow 並走でパリティが取れるまで旧系が正（ADR-V2-003 プレイブック再利用） |
| R5 | **網羅性の証明**: 各フェーズは completeness oracle（全数分類・トレーサビリティ表）で「完全」を機械的に検証する |
| R6 | **P は S の後**: 計画詳細化は仕様カバレッジ表がクローズするまで着手しない |
| R7 | **構造の白紙設計**: アーキテクチャは現行コードの構造からではなく、ツール定義（4 文）+ NP1-NP7 / AP1-AP4 から導出する。現行から継承するのは**挙動仕様と知識**（検知セマンティクス・較正資産・外部 API の癖）であって**構造ではない**。D1 の分解表・サブシステムマップは証拠資料であり、新設計の境界を拘束しない（ADR-V3-003） |

### Phase S — 仕様の完全下ろし（**完了 2026-08-04**）

**成果**: 15 冊 / 765 条項 / 約 8,800 行。カバレッジ表は [v3/S-coverage.md](v3/S-coverage.md)。
D1 の全モジュールが仕様化済または理由付き除外、対応条項の無い BEHAVIOR/CONTRACT テストは 0 件。


- S1: サブシステム別挙動仕様（sensors / scoring / intel pipeline / calibration 機構 / conclusions / AP1-AP4 / auth・通知）
- S2: API 契約書（フロントエンド greenfield の独立作業を可能にする境界）
- S3: データスキーマ仕様 + 新旧移行マップ

- S5: 検証仕様（replay パリティゲート、recall baseline 継承）

規律:
- 各仕様条項は該当コード行を引用（NP6 の流儀を仕様書自体に適用）
- 偶然の挙動は `[ACCIDENTAL]` タグで明示し、保存/破棄をオーナーが判定
- **completeness oracle**: D5 の全挙動テストを仕様条項に対応付けるトレーサビリティ表。対応先のないテスト = 仕様の穴

**出口ゲート**: カバレッジ表クローズ（D1 全モジュールが「仕様化済み」または「理由付き除外」）。
