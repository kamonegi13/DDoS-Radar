Intelligence Operations Guide — MDO C4ISR Strategic Radar

        
    

    


        

        
This platform is an MDO C4ISR Strategic OSINT Radar designed to detect precursor indicators of kinetic operations by correlating signals across three domains: Cyber, Physical, and Information. All data is sourced exclusively from open-source intelligence (OSINT). Sensors run on independent background schedules, and the convergence score is recalculated every SCORE_REFRESH_SEC=60 seconds from the latest cached data. The SYNC button forces an immediate fetch and score update across all active sensors.

        

        

        
本プラットフォームは MDO C4ISR 戦略OSINTレーダー です。サイバー・物理・情報の3ドメインにわたるシグナルを相関分析し、動態作戦の前兆指標を検出します。すべてのデータはオープンソースインテリジェンス（OSINT）のみから取得しています。各センサーは独立したバックグラウンドスケジュールで稼働し、収束スコアは最新キャッシュデータから SCORE_REFRESH_SEC=60 秒ごとに再計算されます。SYNC ボタンで全アクティブセンサーの即時取得とスコア更新を強制実行できます。

        


        

            
            
            
            
            
            
            
            
            
            
        


        

        

        
1. Multi-Domain Sensor Architecture (15 Sensors)


        
Cyber Domain (weight 0.50) — Highest-weighted domain. State-directed cyber operations typically precede kinetic action by 24–72 hours.

        
    
            
  • Cloudflare Radar API [poll: 15 min]: Covers over 20% of global internet traffic. Provides L3 (volumetric) and L7 (application-layer) DDoS telemetry. Spike detection uses HOD (Hour-of-Day) Z-score normalization: the current spike ratio is compared against the historical distribution of the same UTC hour over the past 28 days, eliminating diurnal bias (daytime attack concentrations inflating flat-average baselines). Detects botnet overlap across allied theaters and identifies L7 vector shifts (HTTP flood transitions).
                
    HOD baseline is pre-fetched at startup in a background thread (~7 s per theater): (1) one L7 hourly timeseries call fetches 28 days × 24 h of attack intensity; (2) 28 daily origin-distribution calls provide per-day adversary share. Each HOD slot's spike estimate = daily_avg_spike × (hour_intensity / day_avg_intensity), giving real per-hour baselines immediately without waiting for accumulation. All 24 UTC-hour slots are filled at startup — no warmup period on any slot. Falls back to raw ratio thresholds (2×/4×/6×) only if timeseries is unavailable. Outliers capped at 25×. Sources with absolute share <1% excluded. Non-adversary floor: 3%; adversary floor (CN/RU/KP): 0.5% to retain low-volume state operations. HOD baseline (672 pts/theater) persisted across restarts.
            
    • 
            
  • ThreatFox (abuse.ch) API [poll: 1 hr]: Queries IoCs (Indicators of Compromise) with APT tags published in the past 24 hours. Matches against APT tag or target country name. A hit indicates known APT infrastructure is active in association with the monitored theater. Requires THREATFOX_API_KEY (Auth-Key header).
    • 
            
  • RIPE Stat BGP Routing [poll: 30 min]: Monitors BGP prefix announcement count for the core theater via RIPE NCC. When ≥7 same-UTC-hour samples exist (28-day HOD baseline), anomaly is detected via HOD Z-score: Z < –2.0σ → ANOMALY (+1). During HOD warmup, falls back to flat drop ratio >15% from the previous cycle — a known precursor to internet isolation operations (route withdrawal).
    • 
            
  • DDoS Acceleration Engine [no external poll — computed internally]: Calculates first-order (velocity) and second-order (acceleration) derivatives of the core theater threat score time series via linear regression over a DERIVATIVE_WINDOW=5-point rolling window. Declares an Ambush Pattern when acceleration Z-score (relative to its own rolling history) exceeds AMBUSH_ZSCORE_THRESHOLD=2.0 and both velocity and acceleration are positive — the mathematical signature of exponential escalation. Adds +2 to Cyber domain. Current rate of change is displayed in the VELOCITY meter.
    • 
            
  • GreyNoise Sensor [poll: 30 min] [v9 — Noise Suppressor]: Queries the GreyNoise GNQL Stats API to classify ongoing traffic toward the core theater as TARGETED, MIXED, or NOISE_DOMINANT (internet background scanners). When noise ratio exceeds 70%, all Cyber domain sensor scores are suppressed — preventing mass-scanner events from inflating threat levels during non-adversarial traffic surges. Operates passively (UNKNOWN) when no API key is configured. Requires GREYNOISE_API_KEY (Enterprise GNQL).
    • 
        


        
Physical/Logistics Domain (weight 0.30) — Covers infrastructure, airspace, maritime, and kinetic pre-strike indicators.

        
    
            
  • IODA API (CAIDA) [poll: 5 min]: Tracks BGP-based internet reachability and active probing (ping) success rates. Simultaneous degradation of BGP routing and probing success is classified as a critical infrastructure failure. Cross-validates with the BGP Routing sensor.
    • 
            
  • NASA EONET Wildfire API [poll: 1 hr]: Real-time wildfire and thermal event data from NASA's Earth Observing Natural Event Tracker. Flags events within ±10° of the theater center coordinates. Thermal anomalies near military infrastructure correlate with kinetic strikes, artillery fires, and pre-assault infrastructure destruction. No API key required.
    • 
            
  • OpenSky Network (Civil Airspace) [poll: 30 min]: Monitors civil aircraft count within airport bounding boxes for each theater. Builds a 20-cycle rolling baseline per airport. When ≥7 same-UTC-hour samples are available, severity is determined via HOD (Hour-of-Day) Z-score against the same-hour 28-day history — eliminating diurnal bias from peak/off-peak traffic patterns. HOD Z < –2.0σ → ANOMALY (+2); Z < –3.0σ → CLOSURE (+3). During HOD warmup (<7 same-hour samples), falls back to flat drop ratio: ≥40% → ANOMALY; <5% → CLOSURE. Score is automatically suppressed during severe weather based on OpenWeatherMap data.
                
    Anonymous API: 400 req/day. Set OPENSKY_CLIENT_ID/OPENSKY_CLIENT_SECRET (OAuth2 client credentials) to expand to 4,000 req/day.
    • 
            
  • PeeringDB / IXP Critical Nodes [poll: 4 hr]: Retrieves registration data for Internet Exchange Points (IXPs) associated with monitored theaters. Used as geographic context for interpreting BGP anomalies and physical infrastructure targeting. Displayed as yellow diamonds (◆) on the map.
    • 
            
  • ISR Hotspot Sensor (OpenSky Military ISR) [poll: 30 min]: Monitors 10 ISR_HOTSPOT zones within a 200 km radius — Taiwan Strait, East China Sea ADIZ, Spratly Islands, Korean Peninsula DMZ, Black Sea, Baltic Sea, and others. Aircraft are flagged as ISR patterns if they meet any of: (1) altitude >9,000 m and speed <160 m/s (high-altitude low-speed orbit), (2) squawk 7777 (government/military transponder), or (3) known ISR callsign prefixes (FORTE/JAKE/MYSTIC/RICO/TROLL, etc.). Detection of ≥3 aircraft simultaneously in the same hotspot triggers an ISR Surge, adding +2 to the Physical domain. Operates independently from the civil airspace sensor (targets straits and patrol corridors, not airports).
    • 
            
  • AIS Maritime Sensor (AISHub) [poll: 30 min]: Monitors vessels near 23 chokepoints — Taiwan Strait, Luzon Strait, Malacca Strait, Hormuz, Bab-el-Mandeb, Baltic Sea, Bosphorus, Suez, and others — using AISHub public position data. Detects two anomaly types: (1) AIS Dark Gap — a previously tracked vessel ceases AIS transmission for ≥AIS_DARK_GAP_THRESHOLD=3600 seconds (1 hour) near a chokepoint, consistent with intentional radio silence, submarine positioning, or covert survey vessels; (2) Stationary Anomaly — a non-commercial, non-fishing vessel (AIS type outside 60–89) drifting at <0.5 knots within 50 km of a chokepoint. Adds +1 to Physical domain. Dark Gap vessels appear on the map as red-halo anchor icons.
                
    A 2-second delay is inserted between each chokepoint request to comply with AISHub guest API rate limits.
    • 
            
  • Check-Host Survival Sensor [poll: 10 min] [v9]: Uses the check-host.net API to verify live reachability of critical national infrastructure URLs (government, parliament, central bank, energy grid) for each monitored theater from 5 geographically distributed global nodes (JP/US/DE/NL/FR). Two-phase API: POST check request → GET result (5 s delay). Status levels use HOD Z-score normalization (28-day same-hour baseline, ≥7 samples): HOD Z < –2.0σ AND success_rate < 80% → PARTIAL (+1); HOD Z < –3.0σ AND success_rate < 30% → BLACKOUT (+3). During HOD warmup, falls back to fixed thresholds: OK (≥80%) / PARTIAL (30–79%) → +1 / BLACKOUT (<30%) → +3. PARTIAL scores +1 (not +2) — Maskirovka policy: only confirmed BLACKOUT warrants a strong signal. High-latency responses above CHECKHOST_TIMEOUT_MS=3000 ms are penalized by 50%. Displayed as the SURVIVAL HUD indicator. Configure node list via CHECKHOST_NODES in config.env.
    • 
        


        
Information Domain (weight 0.20) — Propaganda and diplomatic tone analysis. The earliest leading indicator; typically shifts 48–96 hours before an operation.

        
    
            
  • GDELT TimelineTone API [poll: 30 min]: Retrieves media tone for the core theater from the Global Database of Events, Language, and Tone. Triggers an alert (+1) when the tone score falls below –15.0 OR when DoW (Day-of-Week) Z-score < –2.0σ versus the same-weekday 28-day baseline (≥3 same-weekday samples required). DoW normalization prevents false alerts from predictable weekly news cycles (e.g., Monday editorial tone is compared only against previous Mondays). Reference values: Russia→Ukraine pre-conflict period was –12 to –15; day of invasion was –18 to –25. –15.0 is the threshold for active military-tension rhetoric. Auto-suppressed during severe weather.
    • 
            
  • RSS Narrative Burst Sensor [poll: 30 min]: Scans adversary state-aligned RSS feeds selected dynamically by the active Threat Actor configuration (ADVERSARY_NARRATIVE_SOURCES). Sources are bloc-specific: RU → TASS + RIA Novosti; CN → Xinhua + Global Times; IR → Mehr News + Tasnim; KP → KCNA Watch; BY → TASS (RU proxy). Only sources relevant to the configured adversary bloc are polled — eliminating cross-bloc noise. Falls back to all sources when no adversary is configured. Matches theater-specific tactical keywords (e.g., for Taiwan: "military measures", "ultimatum", "median line crossing", "live-fire drills") against article titles and descriptions. Z-score analysis applied to normalized frequency (hit count ÷ total articles) using a 30-day rolling baseline. Alert thresholds: Z > NARRATIVE_ZSCORE_ALERT=2.0 → BURST (+1); Z > NARRATIVE_ZSCORE_CRITICAL=3.0 → CRITICAL_BURST (+2). Deduplication via normalized 60-character title key. Baseline activates after ≥7 days of data accumulation (cold-start guard).
    • 
            
  • Telegram Mirror Sensor [poll: 15 min] [v9]: Scrapes public Telegram channel mirror pages (tgstat.com / telemetr.io fallback) for channels registered in THREAT_ACTOR_MAPPING (hacktivist groups mapped to theaters). No login or API token required. Extracts attack intent keywords (target, ddos, http flood, under attack, op, etc.) and target URLs (.gov / .mil / bank / energy domains). Z-score analysis is applied to keyword frequency (hits per channel scraped) against a 30-day rolling baseline — the same thresholds as the RSS Narrative sensor. Detection levels: CRITICAL_BURST (Z ≥ 3.0, +2) / BURST (Z ≥ 2.0, +1) / INTENT_DETECTED (keyword match, +1) / TARGETS_FOUND (+1) / CLEAR. Baseline activates after ≥7 days of data. Confidence weighting: each channel has a confidence_weight (0.40–0.75) defined in TELEGRAM_CHANNEL_META in geo_data.json; when the mean channel confidence is below TELEGRAM_CLAIM_CONFIDENCE_THRESHOLD=0.5, the score is reduced by 1 to suppress unverified hacktivist claims. Detected channels and target URLs are displayed in the CHAIN panel. A NARRATIVE_BURST event is registered in the escalation chain on burst or intent detection. Configure keywords via TELEGRAM_ATTACK_KEYWORDS.

Noise Reduction & Human-in-the-Loop (HITL) Control

        
    
            
  • OpenWeatherMap (Weather Noise Filter) [poll: 30 min]: When a significant weather event (thunderstorm, blizzard, hurricane, etc.) is detected at the core theater, Physical domain alerts (IODA BGP failure, OpenSky airspace anomaly) and the Information domain alert (GDELT tone) are automatically marked SUPPRESSED and excluded from scoring. This prevents weather events from triggering false escalations.
    • 
            
  • GreyNoise (Automatic Noise Suppressor) [v9]: When GREYNOISE_API_KEY is configured and the GNQL Stats API classifies >70% of traffic toward the theater as internet background noise (scanners, crawlers, opportunistic probes), the suppress_confidence flag is raised. This automatically suppresses all Cyber domain sensor contributions, preventing scanner waves from being misread as targeted attack operations. Operates silently as UNKNOWN when no API key is set.
    • 
            
  • Analyst MUTE (HITL Override): Each sensor in the Evidence Panel has a [ MUTE ] button. Clicking it immediately excludes that sensor's score contribution and recalculates the convergence score. MUTE state is persisted to browser localStorage across sessions. Use this to suppress known false positives while preserving the underlying sensor record. When multiple sensors are muted, domain weights are correctly recalculated using only the remaining active sensors. All 15 sensors support MUTE.

1. マルチドメイン・センサー・アーキテクチャ（15センサー）


        
サイバードメイン（重み 0.50） — 最も重みが高いドメイン。国家指揮による サイバー作戦は、運動学的行動に24〜72時間先行するのが一般的。

        
    
            
  • Cloudflare Radar API [poll: 15 min]: グローバルインターネットトラフィックの20%以上をカバー。L3（ボリューメトリック）およびL7（アプリケーション層）の DDoS テレメトリを提供。スパイク検出にはHOD（時刻帯別）Z スコア正規化を採用：現在のスパイク比率を過去28日間の同じ UTC 時間帯の分布と比較し、昼夜の通信量変動による誤検知バイアスを排除する。同盟国シアター間のボットネット重複を検出し、L7ベクターシフト（HTTP フラッドの遷移）を識別する。
                
    HOD ベースラインは起動時にバックグラウンドスレッドで即時プリフェッチ（シアターあたり約7秒）：(1) L7 hourly timeseries 1回で28日 × 24時間の攻撃強度を取得、(2) 28回の日次オリジン分布コールで敵対国シェアを取得。各 HOD スロットのスパイク推定値 = 日次平均スパイク × (時間帯強度 ÷ 日平均強度) により、蓄積待ちなしで真の時間帯別ベースラインを即時構築。起動時に全24 UTC 時間帯スロットを補完——ウォームアップ期間なし。timeseries 取得不可時のみ生比率閾値（2×/4×/6×）にフォールバック。外れ値は25×に上限設定。絶対シェアが1%未満の送信元は除外。非敵対フロア: 3%; 敵対フロア（CN/RU/KP）: 0.5%。HOD ベースライン（672点/シアター）は再起動をまたいで保持。
            
    • 
            
  • ThreatFox (abuse.ch) API [poll: 1 hr]: 過去24時間に公開された APT タグ付きの IoC（侵害指標）を照会。APT タグまたは対象国名と照合。ヒットは既知の APT インフラが監視シアターに関連して活動中であることを示す。THREATFOX_API_KEY（Auth-Keyヘッダー）が必要。
    • 
            
  • RIPE Stat BGP Routing [poll: 30 min]: RIPE NCC 経由でコアシアターの BGP プレフィックス通知数を監視。同じUTC時間帯のサンプルが7件以上ある場合（28日間HODベースライン）、HOD Zスコアで異常を判定: Z < –2.0σ → ANOMALY (+1)。HODウォームアップ中は前サイクルから15%超のプレフィックス削減にフォールバック — インターネット隔離作戦（ルート撤回）の既知の前兆。
    • 
            
  • DDoS Acceleration Engine [no external poll — computed internally]: コアシアターの脅威スコア時系列に対し、DERIVATIVE_WINDOW=5点ローリングウィンドウで線形回帰による一次（速度）および二次（加速度）微分を算出。加速度Zスコア（独自ローリング履歴対比）が AMBUSH_ZSCORE_THRESHOLD=2.0 を超え、速度・加速度ともに正の場合にアンブッシュパターンを宣言 — 指数的エスカレーションの数学的特徴。サイバードメインに+2を加算。現在の変化率は VELOCITYメーターに表示。
    • 
            
  • GreyNoise Sensor [poll: 30 min] [v9 — Noise Suppressor]: GreyNoise GNQL Stats API を照会し、コアシアターへの継続的トラフィックを TARGETED、MIXED、NOISE_DOMINANT（インターネットバックグラウンドスキャナー）に分類。ノイズ比が70%を超えると、すべてのサイバードメインセンサースコアを抑制 — 非敵対的トラフィックサージ中にマスキャナーイベントが脅威レベルを誇張することを防止。API キー未設定時はパッシブ（UNKNOWN）として動作。GREYNOISE_API_KEY（Enterprise GNQL）が必要。
    • 
        


        
物理ドメイン（重み 0.30） — インフラ、領空、海上、および運動学的先制打撃指標をカバー。

        
    
            
  • IODA API (CAIDA) [poll: 5 min]: BGP ベースのインターネット到達可能性とアクティブプロービング（ping）成功率を追跡。BGP ルーティングとプロービング成功の同時劣化は重大なインフラ障害として分類。BGP ルーティングセンサーとのクロス検証を実施。
    • 
            
  • NASA EONET Wildfire API [poll: 1 hr]: NASA の地球観測自然イベントトラッカーからのリアルタイム山火事・熱異常データ。シアター中心座標の±10°以内のイベントにフラグを立てる。軍事インフラ近傍の熱異常は、運動学的打撃、砲撃、前線インフラ破壊と相関。API キー不要。
    • 
            
  • OpenSky Network (Civil Airspace) [poll: 30 min]: 各シアターの空港バウンディングボックス内の民間機数を監視。空港ごとの20サイクルローリングベースラインを構築。同じUTC時間帯のサンプルが7件以上ある場合、HOD（時間帯別）Zスコア（28日間同時間帯履歴）で重大度を判定し、昼夜間交通量の差異バイアスを排除: HOD Z < –2.0σ → ANOMALY (+2)、Z < –3.0σ → CLOSURE (+3)。HODウォームアップ中（同時間帯サンプル7件未満）はフラットな偏差率にフォールバック: ≥40% → ANOMALY、<5% → CLOSURE。OpenWeatherMap データを基に悪天候時は自動抑制。
                
    匿名API: 400 req/day。OPENSKY_CLIENT_ID/OPENSKY_CLIENT_SECRET（OAuth2クライアント資格情報）を設定すると4,000 req/dayに拡張。
    • 
            
  • PeeringDB / IXP Critical Nodes [poll: 4 hr]: 監視シアターに関連するインターネット交換ポイント（IXP）の登録データを取得。BGP 異常および物理インフラ標的の解釈における地理的コンテキストとして使用。マップ上に黄色のダイヤモンド（◆）として表示。
    •

3. Scoring Engine & Convergence Algorithm

        
The WeightedConvergenceEngine computes a raw threat score from all active, non-suppressed sensor signals, then adds domain convergence bonuses and a sequence bonus. The final score is capped at 15 pts to prevent bonus stacking from producing unrealistic values.


        
Raw Score Components

Domain Convergence Bonus — Added when anomalies appear simultaneously across multiple domains (evidence of coordinated MDO activity rather than an isolated incident):

        
    
            
  • DUAL CONVERGENCE: Any 2 of 3 domains simultaneously active → +1 pt
    • 
            
  • FULL CONVERGENCE: Cyber + Physical + Info all active simultaneously → +2 pt
    • 
        

        
A domain is considered "active" when its weighted score contribution exceeds the domain threshold. FULL CONVERGENCE is the strongest pre-kinetic signal this system can generate.


        
Sequence Bonus — Applied on top of the convergence bonus when a logical escalation chain is confirmed within a 24-hour window. Acts as an anti-confirmation-bias mechanism (does not fire on dramatic signals in a single domain):

        
    
            
  • Chain definition (loose ordering — presence within 24 hr window, strict chronological order not required):
                
      [1] NARRATIVE_BURST  — Tactical keyword Z-score spike in state media or Telegram intent detection
                
      [2] ISR_SURGE        — Reconnaissance aircraft detected at strategic hotspot
                
      [3] SYNC_DDOS        — Coordinated DDoS from ≥2 theaters (high botnet overlap)
                
      [4] FIRMS_ANOMALY    — Thermal/kinetic event from NASA EONET
    • 
            
  • 4/4 confirmed (within 24 hr) → SEQUENCE_FULL_BONUS = +3 pt
    • 
            
  • 3/4 confirmed (within 24 hr) → SEQUENCE_PARTIAL_BONUS = +1 pt
    • 
            
  • <3 events → No bonus (insufficient pattern)
    • 
        


        
Temporal Coherence Bonus [v9] — Applied when first trigger events (SYNC_DDOS or NARRATIVE_BURST) across multiple theaters are temporally synchronized, indicating a single C2 node:

        
    
            
  • C2_SYNC_CONFIRMED  — ≥2 theaters trigger within 60 seconds of each other → +2 pt
    • 
            
  • C2_SYNC_PARTIAL    — ≥2 theaters trigger within 5 minutes of each other → +1 pt
    • 
            
  • Displayed in the HUD as C2-SYNC. Distinguishes nation-state coordinated operations (tight synchronization) from independent hacktivist campaigns (loose timing).
    • 
        


        
Blockade Index (HUD display) — A gauge to quantitatively distinguish "political signaling" DDoS from actual infrastructure neutralization:

        
    
            
  • Formula:  attack_weight = min(DDoS_spike, 10) × (1 + RIPE_drop_pct/100)
    • 
            
  •           infra_deg     = 1.0 − CheckHost_success_rate  (0 = OK, 1 = BLACKOUT)
    • 
            
  •           Blockade Index = min(attack_weight × (0.10 + 0.90 × infra_deg), 10)
    • 
            
  • 10% noise floor: attack is visible even when infra is healthy. 90% infra-weighted: real blockade requires actual connectivity loss. When CheckHost is unavailable (API error), treated conservatively as OK (rate=1.0).
    • 
            
  • NORMAL                        — Index < 1.5: DDoS present but infrastructure reachable. Typical signaling operation.
    • 
            
  • POLITICAL_NOISE               — 1.5–3.9: Significant cyber activity, infrastructure impact unconfirmed.
    • 
            
  • SEVERE_DISRUPTION             — 4.0–6.9: High DDoS + RIPE prefix reduction + partial Check-Host failure simultaneously.
    • 
            
  • INFRASTRUCTURE_NEUTRALIZATION — ≥ 7.0: Large-scale DDoS + BGP withdrawal + infrastructure blackout. Signature of a pre-invasion communications cutoff.

4. Threat Levels

        
Final Score = Raw Score + Convergence Bonus + Sequence Bonus. A 1-cycle hysteresis delay is applied on downgrade only (prevents threshold oscillation). Upgrades are immediate.

        
    
            
  • Level 1 — CRITICAL: Score ≥ 9 AND hard conditions met (core spike >5.0× AND BGP failure confirmed simultaneously). Combined signature of large-scale cyber surge and infrastructure collapse — coordinated pre-invasion blackout operation. Kinetic action probability is extremely high. Activate all emergency procedures.
    • 
            
  • Level 2 — SEVERE: Score ≥ 6 AND ≥ 2 active domains. Single-domain signals (e.g., Cyber-only) cannot reach TL2 regardless of score — multi-domain corroboration is mandatory. Multi-domain threat with direct adversary attribution or significant infrastructure degradation. Immediate commander notification required.
    • 
            
  • Level 3 — HIGH: Score ≥ 4. Significant coordinated anomalies spanning at least 2 sensors. Indicates preparation phase, probing operations, or initial escalation. Enhanced monitoring required.
    • 
            
  • Level 4 — ELEVATED: Score ≥ 2. Early indicators such as deteriorating media tone, isolated BGP events, or minor L7 vector shifts. Consistent with worsening diplomatic tensions or reconnaissance activity.
    • 
            
  • Level 5 — NORMAL: Score < 2. Background noise level. No significant anomalies across monitored domains.
    • 
        


        

        

        
4. 脅威レベル

        
最終スコア = 生スコア + 収束ボーナス + シーケンスボーナス。 ダウングレード時のみ1サイクルのヒステリシス遅延を適用（しきい値振動を防止）。アップグレードは即時。

        
    
            
  • レベル1 — 危機的: スコア ≥ 9 かつハード条件を満たす（コアスパイク >5.0× かつ BGP 障害が同時確認）。大規模サイバーサージとインフラ崩壊の複合特徴 — 協調的侵攻前ブラックアウト作戦。運動学的行動の確率が極めて高い。すべての緊急手順を発動すること。
    • 
            
  • レベル2 — 深刻: スコア ≥ 6 かつ 2ドメイン以上がアクティブ。単一ドメイン（例：サイバーのみ）はスコアに関わらずTL2に到達不可 — 複数ドメインの裏付けが必須条件。直接的な敵対帰属または重大なインフラ劣化を伴うマルチドメイン脅威。直ちに指揮官への通知が必要。
    • 
            
  • レベル3 — 高: スコア ≥ 4。少なくとも2つのセンサーにまたがる重大な協調異常。準備フェーズ、探査作戦、または初期エスカレーションを示す。監視強化が必要。
    • 
            
  • レベル4 — 上昇: スコア ≥ 2。メディアトーンの悪化、孤立した BGP イベント、または軽微な L7 ベクターシフトなどの早期指標。外交的緊張の悪化または偵察活動と整合。
    • 
            
  • レベル5 — 平常: スコア < 2。バックグラウンドノイズレベル。監視ドメイン全体で重大な異常なし。
    • 
        


        

        

        

        

        
5. Threshold Calibration Reference

        
System thresholds are calibrated against the following confirmed historical cases:

        
    
            
  • Russia → Ukraine (24 Feb 2022): BGP routes reduced 10–15% in the 6 hours before invasion. HermeticWiper malware deployed 90 minutes before ground forces crossed. GDELT during pre-conflict period: –12 to –15; day of invasion: –18 to –25. Civil flights ceased 24 hours prior.
    • 
            
  • China → Taiwan Strait (Aug 2022, Pelosi visit): CN-origin DDoS against TW government and media infrastructure spiked 3–5×. GDELT tone during exercises: –13 to –17. No BGP failure (deliberate — PRC signaling, not isolation). Botnet overlap with JP/US-targeted traffic confirmed in post-analysis.
    • 
            
  • DPRK Persistent Operations (ongoing): KP-origin traffic maintains an absolute share of 0.1–0.5%. The adversary 0.5% baseline floor is set specifically to retain these low-volume, high-significance operations that would be undetectable at the 3% non-adversary floor.
    • 
            
  • Iran Internet Shutdown (2019): Near-complete BGP route withdrawal before domestic elections — a full isolation pattern. Corresponds to INFRASTRUCTURE_NEUTRALIZATION on the Blockade Index.
    • 
            
  • Georgia-Russia (Aug 2008): 5-day cyber campaign preceding the ground invasion. GDELT tone dropped from –10 to –14 in the lead-up, then fell below –18 coinciding with the ground assault.

6. Analyst Workflow & Best Practices

        
    
            
  • Prioritize cross-domain corroboration. Do not escalate on single-domain indicators alone. Civilian botnets regularly produce 3–5× DDoS spikes without any military significance. The minimum standard for recommending a Level 2 escalation is FULL CONVERGENCE (Cyber + Physical + Info).
    • 
            
  • Suppress known false positives via HITL MUTE. When a non-adversarial source is confirmed (e.g., airspace anomaly from a major sporting event, BGP shift from legitimate CDN maintenance), mute that sensor in the Evidence Panel. MUTE state persists across reloads via localStorage.
    • 
            
  • Use SITREP for commander reporting. The SITREP button generates a structured situation report including domain breakdown, sensor evidence, and trend indicators.
    • 
            
  • Verify baseline sufficiency. Cloudflare HOD Z-score activates after ≥7 same-hour samples per UTC hour are accumulated. On first launch, a background prefill populates all 24 UTC-hour slots within ~7 s per theater using CF L7 timeseries (hourly intensity) combined with per-day origin distributions — no warmup period is expected under normal conditions. "HOD warmup N/7" in the Evidence Panel indicates the timeseries was unavailable and the slot is accumulating via live polling. RSS Narrative similarly requires ≥7 days of data. Check per-sensor baseline status in the Data Status panel.
    • 
            
  • Read the VELOCITY / AMBUSH meters. VELOCITY is the current rate of change of the threat score (pts per polling cycle ≈ 900 s). Positive (red ↑) = actively deteriorating. Negative (green ↓) = improving. ⚡ AMBUSH (red blink) = the rate of change itself is accelerating — a second-derivative spike. This is the most time-critical signal: it indicates a rapidly compressing attack window.
    • 
            
  • Read the escalation narrative in the CHAIN panel. The CHAIN button (HUD top-right) opens the evidence chain timeline. Displays timestamped [NARRATIVE_BURST → ISR_SURGE → SYNC_DDOS → FIRMS_ANOMALY] escalation events within the past 24 hours. FULL CHAIN (+3 pt) means all 4 event types appeared within 24 hours — a strong indicator of coordinated multi-domain preparation. v9 also registers TELEGRAM_INTENT, MASKIROVKA, C2_SYNC, and INFRA_BLACKOUT in the chain log.
    • 
            
  • Interpreting GDELT tone. –15.0 = threshold for active military-tension rhetoric (v9 calibration). –18 = active crisis framing. Below –20 = historically corresponds to kinetic action imminent or in progress. A 3–5 point drop within a single 30-minute polling cycle is more significant than a gradual decline to the same value.
    • 
            
  • Interpreting the Blockade Index. The index scales with both DDoS intensity and infrastructure degradation: high-volume DDoS that leaves Check-Host nodes reachable produces only the 10% noise floor contribution (Index ≈ 1.0). INFRASTRUCTURE_NEUTRALIZATION (Index ≥ 7.0) requires simultaneous DDoS surge, RIPE BGP withdrawal, AND Check-Host BLACKOUT from global nodes — the pattern observed 30–90 minutes before the Russian ground invasion in February 2022.
    • 
            
  • Interpreting the SURVIVAL HUD (v9). Shows real-time reachability of critical national infrastructure (government, central bank, energy grid) from global nodes. OK = infrastructure reachable. PARTIAL = some nodes report failure — possible DDoS effect or localized disruption. BLACKOUT = critical infrastructure unreachable from multiple global vantage points simultaneously. BLACKOUT + high Blockade Index = likely pre-invasion blackout scenario.
    • 
            
  • Interpreting C2-SYNC (v9). Displays whether attacks across multiple theaters started within 60 seconds (C2 SYNC CONFIRMED) or 5 minutes (PARTIAL). Tight temporal synchronization across geographically separated theaters is the hallmark of nation-state integrated C2 (command and control) rather than loosely coordinated hacktivist activity.
    • 
            
  • Maskirovka detection (v9). If physical outage is confirmed (IODA degraded or Check-Host BLACKOUT) while all narrative channels are simultaneously silent (no RSS burst, no Telegram intent), the system flags a potential Maskirovka (Russian military deception doctrine). PARTIAL Check-Host status alone does not trigger this — only full BLACKOUT, reducing false positives from localized node failures. Physical disruption without accompanying narrative amplification may indicate a genuine kinetic operation rather than a hacktivist campaign — hacktivist groups typically announce targets loudly before and during attacks.
    • 
        


        

        

        
6. アナリストのワークフロー & ベストプラクティス

        
    
            
  • クロスドメインの裏付けを優先する。 単一ドメインの指標だけでエスカレーションしないこと。民間ボットネットは軍事的意義なしに定期的に3〜5倍の DDoS スパイクを生成する。レベル2のエスカレーションを推奨するための最低基準は FULL CONVERGENCE（サイバードメイン + 物理ドメイン + 情報ドメイン）である。
    • 
            
  • HITL MUTE で既知の誤検知を抑制する。 非敵対的な原因が確認された場合（例：大規模スポーツイベントによる領空異常、正規 CDN メンテナンスによる BGP シフト）、エビデンスパネルでそのセンサーをミュートする。MUTE 状態は localStorage によりリロードをまたいで保持される。
    • 
            
  • 指揮官報告には SITREP を使用する。 SITREP ボタンは、ドメイン内訳、センサーエビデンス、トレンド指標を含む構造化された状況報告書を生成する。
    • 
            
  • ベースラインの十分性を確認する。 Cloudflare の HOD Z スコアは UTC 時間帯ごとに同一時間帯サンプル ≥7 件で有効化される。初回起動時はバックグラウンドで全24 UTC 時間帯スロットをシアターあたり約7秒で補完：CF L7 hourly timeseries（時間帯別強度）と日次オリジン分布を組み合わせ、ウォームアップ期間なしで即時有効化される。エビデンスパネルに "HOD warmup N/7" が表示される場合は timeseries が取得できず、ライブポーリングで蓄積中であることを示す。RSS Narrative も同様に≥7日間のデータが必要。
    • 
            
  • VELOCITY / AMBUSH メーターを読む。 VELOCITY は脅威スコアの現在の変化率（ポーリングサイクルあたりのポイント ≈ 900秒）。正（赤↑）= アクティブに悪化中。負（緑↓）= 改善中。⚡ AMBUSH（赤点滅）= 変化率自体が加速中 — 二次微分スパイク。これは最も時間的に緊急なシグナルであり、急速に圧縮される攻撃ウィンドウを示す。
    • 
            
  • CHAIN パネルのエスカレーションナラティブを読む。 CHAIN ボタン（HUD 右上）はエビデンスチェーンタイムラインを開く。過去24時間以内のタイムスタンプ付き [NARRATIVE_BURST → ISR_SURGE → SYNC_DDOS → FIRMS_ANOMALY] エスカレーションイベントを表示。FULL CHAIN（+3 pt）は4種類のイベントタイプすべてが24時間以内に発生したことを意味 — 協調的マルチドメイン準備の強力な指標。v9 では TELEGRAM_INTENT、MASKIROVKA、C2_SYNC、INFRA_BLACKOUT もチェーンログに登録される。
    • 
            
  • GDELT トーンの解釈。 –15.0 = 活発な軍事緊張レトリックのしきい値（v9 キャリブレーション）。–18 = アクティブな危機フレーミング。–20以下 = 歴史的に運動学的行動が切迫または進行中に相当。30分間の単一ポーリングサイクル内での3〜5ポイントの急落は、同じ値への緩やかな下落より重要性が高い。
    • 
            
  • 封鎖インデックスの解釈。 インデックスは DDoS 強度とインフラ劣化の両方に連動してスケールする: Check-Host ノードへの到達可能性を維持したままの高ボリューム DDoS は10%ノイズフロアの貢献のみを生成（インデックス ≈ 1.0）。インフラ無力化（インデックス ≥ 7.0）には、DDoS サージ、RIPE BGP 撤退、そしてグローバルノードからの Check-Host BLACKOUT が同時に必要 — 2022年2月のロシア地上侵攻の30〜90分前に観察されたパターン。
    • 
            
  • SURVIVAL HUD の解釈（v9）。 グローバルノードからの重要な国家インフラ（政府、中央銀行、電力網）のリアルタイム到達可能性を表示。OK = インフラ到達可能。PARTIAL = 一部のノードが障害を報告 — DDoS 影響または局所的障害の可能性。BLACKOUT = 複数のグローバル拠点から同時に重要インフラへの到達不能。BLACKOUT + 高い封鎖インデックス = 侵攻前ブラックアウトシナリオの可能性が高い。
    • 
            
  • C2-SYNC の解釈（v9）。 複数シアターへの攻撃が60秒以内（C2 SYNC CONFIRMED）または5分以内（PARTIAL）に開始されたかどうかを表示。地理的に離れたシアター間での厳密な時間的同期は、緩やかに協調されたハクティビスト活動ではなく、国家が統合した C2（指揮統制）の特徴。
    • 
            
  • Maskirovka 検出（v9）。 物理的障害が確認され（IODA 劣化または Check-Host BLACKOUT）、すべてのナラティブチャンネルが同時に沈黙している場合（RSS バーストなし、Telegram 意図なし）、システムは潜在的な Maskirovka（ロシア軍事欺瞞ドクトリン）にフラグを立てる。Check-Host の PARTIAL 単独ではトリガーされない — ノードの局所的障害による誤検知を削減するため、BLACKOUT のみが対象。ナラティブ増幅を伴わない物理的障害は、ハクティビストキャンペーンではなく真の運動学的作戦を示す可能性がある — ハクティビストグループは通常、攻撃の前後に標的を大声で告知する。
    •

8. Intuition UI — Recognition-Primed Decision (RPD) Components

        
Eleven visual components designed to engage analyst intuition and pattern-recognition (Recognition-Primed Decision) in parallel with numerical computation. Based on Naturalistic Decision Making (NDM) theory; intended for immediate situational awareness formation.


        

            
How to access

            
The TOOLS ▾ dropdown (HUD top-right) allows individual activation of 6 panels: Weather Brief / SALUTE Board / Historical Analog / Ops Clock / GreyNoise / Analyst Notebook (cyan = active). Close each panel individually with ✕. Always-on components (Pulse Display / Radio Silence / Ambient Atmosphere / Threat Terrain) operate automatically without any interaction. The Telegram SIGINT panel is opened via the SIGINT↗ button on the Telegram Mirror row in the CHAIN panel.

        


        
A. Ambient Atmosphere

        
    
            
  • Always active. Subtly shifts the background color of the entire screen in response to threat level (Lv3 → green tint / Lv2 → red-amber tint / Lv1 → deep crimson tint, 2–5 second animation cycle). Leverages peripheral vision to signal "something is wrong" during long monitoring sessions, preventing attentional tunneling.
    • 
        


        
B. Pulse Display

        
    
            
  • Always displayed at bottom-left of map. Renders threat level history (up to 60 cycles ≈ 15 hrs) as a scrolling EKG waveform (Canvas). Level 1 at waveform top, Level 5 at bottom. Waveform color tracks the current Threat Level color. Rate of change (/hr) displayed top-right.
    
            Reading: Rapid upward trend → situation deteriorating quickly. Flat plateau at high level → sustained high-threat environment. Downward turn → signs of de-escalation.
    • 
        


        
C. Operational Clock — TOOLS ▾ → Ops Clock

        
    
            
  • Displays Zulu (UTC) time in large real-time font (second-accurate). Simultaneously shows local time, UTC calendar date, and elapsed time since the last significant event (Level 3 or below). Provides a reference to distinguish genuine inactivity from tactical silence.
    • 
        


        
D. Operational Weather Brief — TOOLS ▾ → Weather Brief

        
    
            
  • Displays the threat state of each domain (Cyber / Physical / Info) using weather metaphors (e.g., Cyber = "Cyber Storm" = large-scale DDoS spike; Physical = "Strait Fog" = AIS dark gap active; Info = "Rising Pressure" = narrative operation intensifying). Enables intuitive understanding without domain expertise, increasing decision speed.
    • 
        


        
E. SALUTE Board — TOOLS ▾ → SALUTE Board

        
    
            
  • Auto-generates a military-standard SALUTE contact report from current threat state:
                
      
                    
    • Size       — Enemy force scale (e.g., 12 botnet sources, 3 state-ASNs)
      • 
                    
    • Activity   — Confirmed activity type (e.g., L7 coordinated surge + narrative burst)
      • 
                    
    • Location   — Target area (e.g., TW; correlated: JP/US)
      • 
                    
    • Unit       — Attribution estimate (e.g., CN attributed — state-ASN match)
      • 
                    
    • Time       — Time of first observed activity (UTC)
      • 
                    
    • Equipment  — Means employed (e.g., L3 volumetric + BGP withdrawal + ISR surge)
      • 
                    
    • +Assessment — Integrated assessment statement from current threat state
      • 
                
    
            
    • 
        


        
F. Historical Pattern Analog — TOOLS ▾ → Historical Analog

        
    
            
  • Compares the current threat score time series (latest 20 cycles) against 5 historical case patterns using Pearson correlation, and displays the top 3 matches:
                
      
                    
    • 🔴 Ukraine Invasion 2022 / 🟠 Taiwan Strait 2022 / 🟡 Iran Shutdown 2019 / 🔵 Georgia-Russia 2008 / ⬜ Normal Baseline
      • 
                
    
            
    • 
            
  • Each card shows similarity % and an overlay graph of the historical pattern (dim) vs. current pattern (cyan). Pearson ≥70% = statistically noteworthy pattern match. Correlation ≠ causation: this is a decision aid, not a prediction.
    • 
        


        
G. Radio Silence Indicator

        
    
            
  • Always displayed in the lower HUD. Detects a state where the threat score is significant (≥3 pts) but velocity is near zero — flagged as QUIET.
    
            QUIET implications: (1) pre-kinetic communications blackout (EMCON), (2) sensor suppression (adversary jamming/spoofing), (3) tactical operational pause. True silence does not mean peace — silence itself is treated as an anomaly to prevent the false perception that "nothing is happening."
    • 
        


        
H. Threat Terrain Overlay

        
    
            
  • Map layer control (top-right) → Threat Terrain. Renders semi-transparent choropleth-style circles over monitored countries scaled to DDoS spike intensity (avg_spike). BGP-confirmed failure = red; spike ≥4× = orange; lower = yellow. Radius proportional to spike intensity (max ~620 km). Allows threat pressure distribution to be perceived geographically at a glance. Countries at or below normal spike levels are not rendered, minimizing noise.

I. GreyNoise Investigator [v9] — TOOLS ▾ → GreyNoise

        
    
            
  • Theater Noise Classification: Shows per-theater GreyNoise classification — TARGETED (traffic is directed, not background scanners), MIXED, or NOISE_DOMINANT (≥70% internet background scan traffic, Cyber domain suppressed).     •

    • DEFCON — Any threat level change (e.g., "Threat Level ▲ 4 → 3 (score: 6)") is recorded immediately.

    • IP_CHECK — Each GreyNoise IP lookup result (IP, noise flag, classification) is logged automatically.

    •

K. Telegram SIGINT — CHAIN panel → SIGINT↗ button on the Telegram Mirror row

B. パルス表示

        
    
            
  • マップの左下に常時表示。 脅威レベルの履歴（最大60サイクル ≈ 15時間）をスクロールする EKG 波形（Canvas）としてレンダリング。波形の上部がレベル1、下部がレベル5。波形の色は現在の脅威レベルの色を追跡。変化率（/時間）を右上に表示。
    
            読み方: 急上昇 → 状況が急速に悪化。高レベルでの平坦プラトー → 持続的な高脅威環境。下降転換 → デエスカレーションの兆候。
    • 
        


        
C. 作戦時計 — TOOLS ▾ → Ops Clock

        
    
            
  • Zulu（UTC）時刻を大きなリアルタイムフォント（秒精度）で表示。ローカル時刻、UTC カレンダー日付、最後の重大イベント（レベル3以下）からの経過時間を同時表示。真の非活動と戦術的沈黙を区別するための参照を提供。
    • 
        


        
D. 作戦気象ブリーフ — TOOLS ▾ → Weather Brief

        
    
            
  • 各ドメイン（サイバードメイン / 物理ドメイン / 情報ドメイン）の脅威状態を気象メタファーを使用して表示（例: サイバードメイン = "Cyber Storm" = 大規模 DDoS スパイク；物理ドメイン = "Strait Fog" = AIS ダークギャップ活動中；情報ドメイン = "Rising Pressure" = ナラティブ作戦が激化）。ドメイン専門知識なしに直感的な理解を可能にし、意思決定速度を向上。
    • 
        


        
E. SALUTE ボード — TOOLS ▾ → SALUTE Board

        
    
            
  • 現在の脅威状態から軍事標準の SALUTE 接触報告書を自動生成:
                
      
                    
    • Size（規模）       — 敵戦力の規模（例: 12のボットネット送信元、3つの国家 ASN）
      • 
                    
    • Activity（活動）   — 確認された活動タイプ（例: L7 協調サージ + ナラティブバースト）
      • 
                    
    • Location（位置）   — 標的エリア（例: TW；相関: JP/US）
      • 
                    
    • Unit（部隊）       — 帰属推定（例: CN 帰属 — 国家 ASN 一致）
      • 
                    
    • Time（時刻）       — 最初の観察活動の時刻（UTC）
      • 
                    
    • Equipment（装備）  — 使用手段（例: L3 ボリューメトリック + BGP 撤退 + ISR サージ）
      • 
                    
    • +Assessment（評価） — 現在の脅威状態からの統合評価文
      • 
                
    
            
    • 
        


        
F. 歴史的パターンアナログ — TOOLS ▾ → Historical Analog

        
    
            
  • Pearson 相関を使用して現在の脅威スコア時系列（最新20サイクル）を5つの歴史的事例パターンと比較し、上位3つの一致を表示:
                
      
                    
    • 🔴 ウクライナ侵攻2022 / 🟠 台湾海峡危機2022 / 🟡 イランシャットダウン2019 / 🔵 ジョージア〜ロシア2008 / ⬜ 平常ベースライン
      • 
                
    
            
    • 
            
  • 各カードには類似度％と、歴史的パターン（薄暗）対現在のパターン（シアン）のオーバーレイグラフを表示。Pearson ≥70% = 統計的に注目すべきパターン一致。相関 ≠ 因果関係: これは意思決定支援ツールであり、予測ではない。
    • 
        


        
G. 無線沈黙インジケーター

        
    
            
  • 下部 HUD に常時表示。 脅威スコアが有意（≥3 ポイント）であるが速度がゼロに近い状態を検出 — QUIET としてフラグ。
    
            QUIET の含意: (1) 運動学的行動前の通信ブラックアウト（EMCON）、(2) センサー抑制（敵対者によるジャミング/スプーフィング）、(3) 戦術的作戦停止。真の沈黙は平和を意味しない — 沈黙自体が「何も起きていない」という誤った認識を防ぐための異常として扱われる。
    • 
        


        
H. 脅威テレイン オーバーレイ

        
    
            
  • マップレイヤーコントロール（右上）→ Threat Terrain。 DDoS スパイク強度（avg_spike）にスケールした半透明コロプレス型サークルを監視国の上にレンダリング。BGP 確認済み障害 = 赤；スパイク ≥4× = オレンジ；それ未満 = 黄色。半径はスパイク強度に比例（最大 ≈620 km）。脅威圧力の分布を地理的に一目で把握可能。通常スパイクレベル以下の国はレンダリングされず、ノイズを最小化。
    • 
        


        
I. GreyNoise インベスティゲーター [v9] — TOOLS ▾ → GreyNoise

        
    
            
  • シアターノイズ分類: シアターごとの GreyNoise 分類を表示 — TARGETED（トラフィックが指向性を持ち、バックグラウンドスキャナーではない）、MIXED、または NOISE_DOMINANT（≥70%インターネットバックグラウンドスキャントラフィック、サイバードメイン抑制）。GREYNOISE_API_KEY（Enterprise GNQL）が必要。Enterprise キーなしの場合、分類は UNKNOWN を表示。
    • 
            
  • IP インベスティゲーター（Community API）: GreyNoise Community API 経由で任意の IPv4 アドレスを手動オンデマンド照会。返却値: ノイズフラグ（true = インターネット全体スキャナー）、riot フラグ（既知の無害なインフラ）、分類、エンティティ名、最終確認日。結果は IP ごとに24時間キャッシュ。レート制限: 50 req/day（Community プラン）。GREYNOISE_API_KEYが必要。各照会はアナリストノートブックに自動ログ。
    • 
            
  • 調査ログ: 直近20件の IP 照会のセッション履歴をブラウザの localStorage に保持。ライブ脅威テレメトリパネルで浮上した疑わしい送信元 IP のトリアージにこのパネルを使用。
    • 
        


        
J. アナリストノートブック [v9] — TOOLS ▾ → Analyst Notebook

        
    
            
  • アナリスト評価: ドロップダウン（NOMINAL / WATCHFUL / CONCERNED / CRITICAL / HOSTILE）と5段階の信頼度スケール（1 = LOW … 5 = HIGH）。自動化された脅威スコアとは独立して、アナリストの現在の状況認識を記録。セッションをまたいで保持。
    • 
            
  • 手動メモ: 観察、仮説、推論を記録するための自由テキスト入力。Ctrl+Enter を押すか LOG をクリックしてシフトログに追記。各エントリはタイムスタンプ付き（UTC）。
    • 
            
  • 自動ログ: アナリストの操作なしに3種類のイベントタイプが自動記録:
                
      
                    
    • DEFCON — すべての脅威レベル変化（例: "Threat Level ▲ 4 → 3 (score: 6)"）を即座に記録。
      • 
                    
    • IP_CHECK — 各 GreyNoise IP 照会結果（IP、ノイズフラグ、分類）を自動ログ。
      • 
                    
    • MUTE / UNMUTE — センサーのミュート/ミュート解除操作を、アナリストが提供した理由とともに記録（オプションのプロンプトダイアログ）。
      • 
                
    
            
    • 
            
  • ウォッチハンドオフ: 下部の「WATCH FOR」フィールドには次のアナリストシフトへの引継ぎノートを保持。EXPORT を使用してシフト交代またはインシデント報告のためにシフトログ全体をクリップボードにコピー。
    • 
        


        
K. Telegram SIGINT — CHAIN パネル → Telegram Mirror 行の SIGINT↗ ボタン

        
    
            
  • 目的: Telegram Mirror センサーインテリジェンスを構造化された SIGINT フォーマットで表面化する専用フローティング/ドッキング可能パネル — リアルタイムステータス、シアター活動内訳、スクロール可能な傍受ログ、監視チャンネルリストを統合。
    • 
            
  • ステータスバッジ: 現在のセンサー状態を表示 — INTENT DETECTED / TARGETS FOUND / CLEAR / PENDING — 最終ポーリングタイムスタンプと成功/失敗インジケーター付き。
    • 
            
  • シアター活動グリッド: アクティブシアターごとに1タイル。各タイルにシアターコード、総ヒット数、最高検出レベルバッジを表示。空状態テキストはコンテキスト対応: 最初のサイクル前は「センサー未ポーリング」；ヒットなしでポーリング完了後は「チャンネル活動未検出」。タイルをクリックすると、その シアターのみに傍受ログをフィルタリング。
    • 
            
  • 傍受ログ: 最大50件の検出を含む時系列リングバッファ。ポーリングをまたいでメモリ内に保持（サーバー再起動でクリア）。各エントリにはチャンネル名（リンク付き）、タイムスタンプ（UTC）、検出タイプバッジ、一致キーワード、標的となった政府/軍事ドメイン、周辺コンテキストを示す200文字テキストスニペットを表示。エントリの色分け: 赤ボーダー = INTENT、琥珀 = TARGETS。チャンネル名をクリックするとミラー URL が開く。ログヘッダーの [CLEAR] ボタンでログを消去（POST /api/telegram_log/clear を呼び出す）。シアタータイルまたは [All Theaters] でフィルターをリセット。
    • 
            
  • チャンネルリスト: THREAT_ACTOR_MAPPING に設定されたすべてのチャンネルを、関連するシアターとミラー URL とともに一覧表示。チャンネルカバレッジの確認と監視への新規チャンネル追加の参照として使用。
    • 
            
  • 誤検知抑制: センサーは部分文字列衝突を避けるため、単語境界正規表現マッチング（\b）を適用（例: "target" が "targeting" に一致しないよう）。2文字以下のキーワードは完全にスキップ。複数単語キーワードとハッシュタグは完全部分文字列マッチングを使用。

10. Administration & Extended Features

        
Features added for production deployment: user authentication, alert notifications, plugin sensors, and historical analysis.


        
A. User Management — TOOLS ▾ → User Management

        
    
            
  • Authentication: JWT-based login with access tokens (default: 1h expiry) and refresh tokens (24h). On first startup, a default admin user is created with the password set in DEFAULT_ADMIN_PASSWORD (default: "admin"). Change this immediately in production.
    • 
            
  • Roles: Three roles control access — admin (full access, user management), analyst (operational access), viewer (read-only). Only admins can add/delete users and change roles.
    • 
            
  • User Management Panel: Login with admin credentials → view all users with role/created/last-login. Inline role selector for instant role changes. PW button to reset passwords. DEL button to delete users (with confirmation). Self-deletion and self-role-change are blocked for safety.
    • 
            
  • Per-User Settings: Each user stores their own theater configuration (core, pins, correlates, adversaries, muted sensors, language) via PUT /api/auth/settings.
    • 
        


        
B. Alert Notifications

        
    
            
  • Channels: Slack (Incoming Webhook), Microsoft Teams (MessageCard), and generic HTTP POST webhook. Configure URLs in Config → Advanced Settings → Alert Notifications.
    • 
            
  • Events: Threat Level changes (escalation/de-escalation), Ambush pattern detection, Sequence chain completion (FULL_CHAIN/PARTIAL), and persistent sensor failure.
    • 
            
  • Debounce: Same-type alerts are suppressed for NOTIFY_DEBOUNCE_SEC seconds (default: 300) to prevent notification storms.
    • 
            
  • Safety: All dispatches run in background daemon threads. Set NOTIFY_ENABLED=false to disable all notifications globally.
    • 
        


        
C. Plugin Sensors

        
    
            
  • Dynamic Loading: Place a Python file containing a BaseSensor subclass in the plugins/ directory. The plugin loader automatically discovers, imports, and registers it at startup.
    • 
            
  • Configuration: PLUGIN_DIR (directory path), PLUGIN_ENABLED (* for all, or comma-separated filenames), PLUGIN_DISABLED (explicit exclusion list).
    • 
            
  • Duplicate Protection: If a plugin sensor name conflicts with a built-in sensor, the plugin is skipped with a warning.
    • 
        


        
D. History Analysis — TOOLS ▾ → History Analysis

        
    
            
  • Theater Selector: Dynamically populated from all configured theaters (pins + correlates + core) and any theaters with recorded data. Fetched via /api/history/theaters.
    • 
            
  • Time Range: 24h / 3 days / 7 days / 14 days / 28 days. Data is retained up to 28 days (8064 data points at 5-minute intervals).
    • 
            
  • Threat Score Trend: Canvas line chart with a fixed Y-axis (0–25) and severity zone backgrounds: Normal (0–2, green), Elevated (2–5), Warning (5–10, amber), Severe (10–18, orange), Critical (18–25, red). This fixed scale ensures that a score of 7 is always visually contextualized as "Warning zone" regardless of the current data range.
    • 
            
  • Hour-of-Day Baseline: Bar chart of CF Spike averages by hour (0–23), colored by intensity. Useful for identifying temporal attack patterns.
    • 
            
  • Sequence Events: Escalation chain events grouped by date with type summary badges (e.g., BURST×3 SURGE×1). Event types: NARRATIVE_BURST, ISR_SURGE, SYNC_DDOS, FIRMS_ANOMALY, AIS_DARK_GAP, etc.
    • 
            
  • Recent Alerts: Displays threat level transitions instead of raw alert entries. Each row shows: time → TL badge → duration at that level → peak score. Consecutive same-TL alerts are collapsed into a single transition entry, making it easy to see how long each threat level persisted. Grouped by date.
    • 
            
  • Export: Download all historical data as JSON via the Export button or GET /api/history/export?theater=TW (admin only).
    • 
        


        
E. Database Backend (SQLite)

        
    
            
  • All persistent state is stored in SQLite with WAL mode for concurrent read/write performance. The database file is at persistence/radar.db.
    • 
            
  • On first startup after migration, existing state.json data is automatically migrated to SQLite and the JSON file is renamed to state.json.migrated as backup.
    • 
            
  • Per-sensor caches remain in memory for performance; all other state (baselines, HOD data, sequence events, alerts, threat levels) is persisted to SQLite.
    • 
        


        

        

        
10. 管理機能 & 拡張機能

        
本番運用向けに追加された機能: ユーザー認証、アラート通知、プラグインセンサー、履歴分析。


        
A. ユーザー管理 — TOOLS ▾ → User Management

        
    
            
  • 認証: JWT ベースのログイン。アクセストークン（デフォルト: 1時間有効）とリフレッシュトークン（24時間）を使用。初回起動時に DEFAULT_ADMIN_PASSWORD（デフォルト: "admin"）で admin ユーザーが自動作成される。本番環境では即時変更すること。
    • 
            
  • ロール: 3つのロールでアクセスを制御 — admin（全権限、ユーザー管理可）、analyst（運用アクセス）、viewer（読み取り専用）。ユーザーの追加・削除・ロール変更は admin のみ可能。
    • 
            
  • ユーザー管理パネル: admin 認証情報でログイン → 全ユーザーのロール/作成日/最終ログインを表示。インラインのロール選択で即時変更。PW ボタンでパスワードリセット。DEL ボタンでユーザー削除（確認ダイアログ付き）。安全のため自分自身の削除とロール変更はブロック。
    • 
            
  • ユーザー別設定: 各ユーザーは独自のシアター設定（コア、ピン、相関国、敵対者、ミュートセンサー、言語）を PUT /api/auth/settings で保存可能。
    • 
        


        
B. アラート通知

        
    
            
  • チャネル: Slack（Incoming Webhook）、Microsoft Teams（MessageCard）、汎用 HTTP POST Webhook。URL は Config → 詳細設定 → アラート通知で設定。
    • 
            
  • イベント: 脅威レベル変化（エスカレーション/デエスカレーション）、アンブッシュパターン検出、シーケンスチェーン完了（FULL_CHAIN/PARTIAL）、センサーの持続的障害。
    • 
            
  • デバウンス: 同一タイプのアラートは NOTIFY_DEBOUNCE_SEC 秒間（デフォルト: 300）抑制され、通知の嵐を防止。
    • 
            
  • 安全性: すべてのディスパッチはバックグラウンドのデーモンスレッドで実行。NOTIFY_ENABLED=false で全通知をグローバルに無効化可能。
    • 
        


        
C. プラグインセンサー

        
    
            
  • 動的ロード: BaseSensor サブクラスを含む Python ファイルを plugins/ ディレクトリに配置。プラグインローダーが起動時に自動的に検出、インポート、登録。
    • 
            
  • 設定: PLUGIN_DIR（ディレクトリパス）、PLUGIN_ENABLED（* で全プラグイン、またはカンマ区切りのファイル名）、PLUGIN_DISABLED（明示的除外リスト）。
    • 
            
  • 重複保護: プラグインセンサー名が組み込みセンサーと競合する場合、警告とともにスキップ。
    • 
        


        
D. 履歴分析 — TOOLS ▾ → History Analysis

        
    
            
  • シアターセレクター: 設定済みの全シアター（ピン + 相関国 + コア）およびデータ記録のあるシアターから動的に生成。/api/history/theaters から取得。
    • 
            
  • 時間範囲: 24時間 / 3日間 / 7日間 / 14日間 / 28日間。データは最大28日間保持（5分間隔で8064データポイント）。
    • 
            
  • 脅威スコア推移: 固定Y軸（0〜25）と重要度ゾーン背景色を持つ Canvas 折れ線グラフ: 正常（0〜2, 緑）、警戒（2〜5）、警告（5〜10, 琥珀）、深刻（10〜18, オレンジ）、危機的（18〜25, 赤）。この固定スケールにより、例えばスコア7は現在のデータ範囲に関係なく常に「警告ゾーン」として視覚的に文脈化される。
    • 
            
  • 時間帯別ベースライン: CF スパイク平均を時間帯（0〜23時）ごとに棒グラフで表示、強度で色分け。時間的な攻撃パターンの特定に有用。
    • 
            
  • シーケンスイベント: 日付別にグループ化されたエスカレーションチェーンイベント。タイプ別サマリーバッジ付き（例: BURST×3 SURGE×1）。イベントタイプ: NARRATIVE_BURST、ISR_SURGE、SYNC_DDOS、FIRMS_ANOMALY、AIS_DARK_GAP 等。
    • 
            
  • 最近のアラート: 生のアラートエントリではなく、脅威レベルの遷移を表示。各行: 時刻 → TLバッジ → そのレベルでの滞在時間 → ピークスコア。連続する同一TLアラートは1つの遷移エントリに圧縮され、各脅威レベルの持続時間が一目で把握可能。日付別グループ化。
    • 
            
  • エクスポート: Export ボタンまたは GET /api/history/export?theater=TW で全履歴データを JSON としてダウンロード（admin のみ）。
    • 
        


        
E. データベースバックエンド（SQLite）

        
    
            
  • すべての永続状態は WAL モードの SQLite に保存され、並行読み書き性能を確保。データベースファイルは persistence/radar.db に配置。
    • 
            
  • マイグレーション後の初回起動時に、既存の state.json データが自動的に SQLite にマイグレーションされ、JSON ファイルはバックアップとして state.json.migrated にリネーム。
    • 
            
  • センサーごとのキャッシュはパフォーマンスのためメモリに保持。その他すべての状態（ベースライン、HOD データ、シーケンスイベント、アラート、脅威レベル）は SQLite に永続化。
    •
